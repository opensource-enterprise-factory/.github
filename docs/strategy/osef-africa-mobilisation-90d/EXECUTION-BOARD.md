## Configuration conseillée du GitHub Project transversal

**Nom :** OSEF Africa — Growth, Partnerships & Community

**Vues :** Board (Status), Table (Owner, Workstream, Phase), Roadmap (dates approuvées), Blocked (dépendances).

**Colonnes Status :** Backlog → Ready → In Progress → Review → Blocked → Done.

**Champs :**
- Workstream : ADVISE / BUILD / OPERATE.
- Owner role : Direction / Partnerships & Communications / Engineering & Community / Product teams.
- Phase : J1–J30 / J31–J60 / J61–J90.
- Priority : P0 / P1 / P2.
- Evidence : Missing / In Review / Verified.
- Decision : Pending / Approved / Rejected.

**Attention :** les champs ci-dessus n'ont pas été créés automatiquement dans GitHub Projects. Ce document en définit seulement le modèle.

## Rituels
- **Lundi (30 min)** : chaque issue a une prochaine action, un responsable et une date indicative.
- **Jeudi (20 min)** : débloquer les dépendances et vérifier les preuves.
- **Fin de mois (45 min)** : comparer chiffres réels et objectifs, arrêter ou réorienter les initiatives qui n'apportent pas de résultats.

## Critères « Done »
1. Le livrable existe et peut être ouvert par le relecteur habilité.
2. Les faits et les objectifs sont distingués.
3. Les données prospect et informations commerciales restent privées.
4. Une décision, un statut et la prochaine étape sont documentés.
5. La communication externe a été validée lorsque des partenaires ou clients sont nommés.
